# Native resource workload (diagnostic, not an optimization)

Exact Cubism5.3.02, bundled JVM17, existing reviewed JAR/BAT and heavy fixture hashes in [experiment ledger](NATIVE-PERFORMANCE-EXPERIMENTS.md). Product flags all off. The JDK-only auxiliary is excluded from product packaging. Reuses the existing common runner and proc CPU/DRM/RSS/PSS sampler, not a second launcher.

## Workload

After task-document readiness, collect300 seconds with the existing memory protocol:30 seconds natural idle;60 native modeling zoom-in/out commands paced at least500ms with actual camera-scale changes; exact original raw camera-scale restoration through native setter/listeners, camera update and repaint; dirty/Undo history unchanged;30 seconds restored idle; native close of the single clean task document;120 seconds natural closed-document idle. Remaining sampler time is labeled by explicit phase boundaries, not counted as zoom. The observer retains only a weak document reference after closing, no image graph or host model snapshots. No force-GC, model saving, changed heap limits or skipped rendering. A weak reference not cleared without a natural collection is inconclusive, not proof of a leak. P03-b in the ledger retains the failed120-action/UI-scale-restore protocol; never combine its timings as an identical run.

Current P03-c amendment: before sampler ready, normalize the task-copy camera to a native scale step using one zoom-in/out pair. Record original fit scale separately. “Original” in the timed workload means this normalized starting scale, not the arbitrary initial fit ratio. The latter was not exactly restorable through native reciprocal/listener updates in P03-b/c; both failures remain recorded. Timed actions still require exact raw and derived scale restoration, not a relaxed tolerance.

The current public SDK command enum does not expose modeling zoom-in/out or document-close. This auxiliary invokes those exact native commands on EDT; it does not expose reflection to plugins or change product APIs. Each action requires the same document/view and task window. Zoom is not parameter dragging and not window resize. Numerical camera/dirty/Undo checks do not establish every visual pixel or every interactive workflow.

## Native released-image attribution (test-only)

The auxiliary now takes two bounded readonly snapshots: after `idle.end` before `zoom.begin`, and after `restored.end` before native close. Exclude `retain.beforeZoom.begin/end` and `retain.beforeClose.begin/end` from idle/zoom timing; this is an amended diagnostic cohort, not an identical historical baseline. Each snapshot verifies raw field shapes and class origins under the already hash-verified host. It reads current model groups and `_filteredImage` directly: never the lazy `getFilteredImage()` or pixel capture/PNG helpers. Coverage is **model-image filtered resources**, not every cache/atlas-only image/GPU allocation.

`retain.beforeZoom.*`/`retain.beforeClose.*` report identity-deduplicated resource/user counts, active/released records, released records whose user is absent from that resource's active set, model-user source association, coverage/status/reason and durationNs. Caps are 4096 groups, 4096 model images/resources and 16384 combined records, with a 250ms cooperative deadline including layout setup. This is not a hard scheduling bound. A resource's relationship counts/cohort are committed only after bounded identity consistency checks; concurrent changes can still evade checks (including ABA), so COMPLETE means completed traversal, **not an atomic heap snapshot**. PARTIAL/UNSUPPORTED are not zero-total conclusions. Counts are not retained bytes or proof that a user has no other legitimate references.

Only scalar Properties and bounded WeakReference cohorts escape capture. Only the before-close cohort persists; `retain.closed.*` and `retain.final.*` count cleared/not-cleared references using `refersTo(null)`, never reacquiring referents. The auxiliary preserves document/view/camera/dirty/Undo guards, adds no native ownership mutations or GC. Overall workload PASS is separate from `retain.attributionStatus=COMPLETE|INCOMPLETE`; incomplete attribution must not be reported as completed optimization acceptance.

## Post-close native ownership attribution (test-only, not yet run on the host)

The auxiliary additionally takes four bounded readonly ownership captures: a control capture while the document is legitimately open and strongly held (`ownership.idle.*`, after `idle.end`), a pre-close capture before the close command (`ownership.beforeClose.*`), and two post-close captures (`ownership.closed120.*` about 120s after the close and `ownership.closedFinal.*` at the sampler end). Exclude `ownership.*.begin/end` from idle/zoom timing; this is an amended diagnostic cohort, not an identical historical baseline.

Each capture counts the static registry list, looks for an entry whose file path string equals the recorded fixture path, and reads that entry's referrer count and sanitised referrer class names, plus the controller current doc/view nullability and the private `viewContextHistory` size, null-element count, non-null-document count and identity-matches to the closed document. Nothing is removed, disposed, cleared or collected; the history field is read with `trySetAccessible` and never written.

The recorded fixture is matched by file path string only, so the probe never has to hold the closed document or its model source. Two accessor families are reported separately because they return different objects: the entry base class `b()`/`c()` describe the entry's loader wrapper, while only the concrete model entry declares `f()` returning the recorded `CModelSource`. Only `fixtureCarriedSourceIsRecordedSource` (identity-only, via `refersTo`) states that the recorded source is still carried by the surviving entry; `fixtureLoadedFlag`/`fixtureWrapperPresent` alone do not.

Every capture reports `status` (`COMPLETE`/`PARTIAL`/`UNSUPPORTED`), `reason`, `durationNs`, `referrersExamined` and the before/after weak-pair samples. Caps are 4096 registry entries, 4096 history views, 16384 combined referrer records and a 250ms cooperative deadline including layout setup; this is not a hard scheduling bound. Counts are staged and published only for a `COMPLETE` capture, so an incomplete capture reports no count at all instead of a partial or fabricated zero, and `PARTIAL`/`UNSUPPORTED` are never zero-total conclusions. `ownership.attributionStatus` is the aggregate: `COMPLETE` only when all four captures are `COMPLETE`, otherwise `INCOMPLETE`; incomplete attribution must not be reported as optimization acceptance. `documentWeakBefore != documentWeakAfter` for one capture invalidates that capture as an observer effect. This remains a bounded, non-atomic traversal: COMPLETE means the traversal finished, not an atomic heap view, and it is not a GC-root walk or retained-size measurement.

Focused offline tests: `python3 -B scripts/test/test_native_image_retain_observation.py`. Synthetic host-shaped objects throw on equals/hashCode/toString/materialization. Tests cover bounded counts, deduplication, unsupported layouts/users, mutation windows, deadline boundaries and weak-state shape without official class loading or forced GC. Focused offline tests for the ownership captures: `python3 -B scripts/test/test_native_close_ownership_observation.py` (synthetic registry/history graphs, bounds, deadline sweep, mutation windows, accessor-shape rejection and forbidden call sites) plus `python3 -B scripts/test/test_native_resource_policy.py`.
