# The aggregate gate graph as data. Read twice, both fail-closed:
#   buildSrc/src/main/java/dev/turboism/gradle/internal/GateManifest.java  registers the tasks
#   scripts/test/test_ci_coverage.py                                       asserts the contract
#
# Grammar, one declaration per line. `#` starts a comment (outside quotes); blank lines are free.
#
#   aggregate <name> group="…" owner="<workflow>:<line>"|"via:<aggregate>"
#                     harm="…" description="…" [release-flags] [require-xvfb]
#   member <aggregate> <task path | @token>
#   manual|opt-in|orphan <task> reason="…" [doc="<path>:<line>"]
#
# `owner` names the workflow that launches the aggregate and the line that does it, or `via:` the
# aggregate that launches it. `harm` cites the concrete user-harm mode when the gate is absent
# (ARCHITECTURE_GOVERNANCE.md); both are mandatory, and a member must name a declared aggregate.
# Member order is the registration order, so reordering a member list is a behaviour change.
#
# `@token` members are the dynamic collections the script binds (see verification.gradle.kts); an
# unbound token, or a bound token no member names, fails the load. Every other member stays a lazy
# dependency by task name, so a task registered by a later script still resolves.
#
# Routes explain why a task is not an aggregate member. `manual` is run by a human on demand,
# `opt-in` is reached outside the static aggregate graph (a module `check` alias, a dynamic
# cross-project edge, or an explicit workflow lane), and `orphan` is a tombstone with no route at
# all that a maintainer must resolve. Every `check*`/`*SelfTest`/`verify*` task must be a member or
# routed, so a gate cannot shrink without a diff.
