Implemented behavior
- EDT-owned view state; one serial worker owns disk/network operations and owned leases.
- Stable failed planning until explicit retry; generation-checked preview results.
- Independent cancellation controls per download; stale results cannot revive cancelled batches.
- Selection is frozen while downloading/committing. Editing a prepared selection invalidates it.
- Explicit framework-only choice remains possible when the plugin catalog is unavailable.
  It does not bypass local installed/pending compatibility checks or framework signatures.
- Downloads do not publish plugin pending operations. User installation consent commits the
  plugin batch, then schedules the framework. A failure between these two journals is reported
  as partial success, not a globally atomic transaction.
- Prepared plugin descriptors support both current and authenticated target APIs. Final checks
  use actual installed archive metadata, existing pending installs/uninstalls and required
  dependency ranges; they do not silently enable disabled dependencies or downgrade plugins.
- Batch publication rejects changed pending snapshots, duplicate IDs and a corrupt last item.
- The root-bound gate serializes automatic stage/hot-apply with manual lease acquisition;
  acquisition/cleanup never waits on the EDT. Framework pending/health journals suspend auto-updates.
- Closing the view does not cancel an already-consented commit or delete journalled packages.
