## Adopted Behaviour Boundaries

- Codex: `splitCodexMcpToolResultImages` separates an MCP image from the text result; Turboism keeps the ACP typed content and hands the image to the existing UI through the image callback instead of putting base64 into chat text.
- Pi: distinguish the prompt ACK, `agent_end`, and `agent_settled`; an end event carrying `willRetry` does not complete the turn directly. A cancel ACK never passes as a host modelling task cancellation.
- Pi: decide vision capability from the model `input`. Turboism refuses an image prompt on a model without a verified image input and sends no prompt to that model.
- Tool results keep their native structure, and ordinary text stays readable; a Claude base64 source becomes an ACP image, and an embedded resource keeps its resource type.
- The Paseo MCP adapter of Pi mainly maps tool names and does not prove that the Turboism resource discovery chain is complete. Turboism adds read-only list, templates, and read model tools, registers them by capability, reads the live server catalog on every call, and keeps pagination.

## Harness Communication Contract and Acceptance Checklist

The table below states the requirements for later implementation and review. Paseo behaviour serves as a protocol reference only; its test or compatibility scope never becomes Turboism acceptance evidence. The native provider and the ACP-v1 adapter are accepted separately.

| Stage | Paseo reference location | Turboism contract and required cases |
| --- | --- | --- |
| Session and turn identity | `interrupt()` in `codex-app-server-agent.js` | Store the client request, the thread, the native turn, and the modelling operation identity separately. When the start ACK precedes turn/started, a cancel still binds the original turn; a late event cannot end a new turn |
| Terminal state | `handleTurnBoundaryEvent()` in `pi/agent.js` | A prompt ACK only confirms receipt. A Pi that supports settled waits for agent_settled; compatibility with an old agent_end without willRetry needs separate admission; test retries, duplicate terminal states, interleaved events, and process exit |
| Cancellation | the `turn/interrupt` request in `codex-app-server-agent.js`; `interrupt()` in `pi/agent.js` | Keep the cancel request return, the turn terminal state, and the agent cancel plus MCP and host commit states separate. On an unknown write result, check the operation first and never replay automatically; test a start race, a late result after a cancel ACK, and a disconnect |
| Permission round trip | the commandExecution and fileChange requestApproval handlers in `codex-app-server-agent.js` | An approval binds the original request and target, and a refusal, expiry, or disconnect must close it; string, array, and object digests stay readable and sanitized; a Paseo shell or file approval never replaces a Cubism file grant |
| Tool images | `splitCodexMcpToolResultImages()` in `codex/tool-call-mapper.js`; `pi/tool-call-mapper.js` | Keep text, image, resource, and resource_link typed; verify model context and Swing display separately; make the image budget and MIME validation explicit, never turn an error result into success, and never put base64 into chat text |
| Model vision capability | `piModelSupportsImageInput()` in `pi/agent.js` | Decide from the image input of the current running model and decide again after a model switch; state clearly when the capability is unknown; a UI that can display an image does not prove the model consumed it |
| MCP discovery and recovery | `pi/extensions/pi-mcp-adapter/index.js`; the Turboism Pi extension | Discover tools, resources, and templates separately; save the cursor and detect a duplicate page; refresh the catalog after recovery. A Paseo tool mapping does not prove the resource bridge is complete; prompts are a separate optional scope |
