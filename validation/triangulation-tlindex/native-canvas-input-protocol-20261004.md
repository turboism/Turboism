# T091 受控画布输入诊断

目的：受控复现 T090 没有覆盖的非空事件控件分支，核验原生命令重绘是否触发网格复制、缓存刷新和索引变化。一次独立 5303 FIFO 任务，三轮命令；不重试 T087/T088/T089/T090，不授予性能验收。

使用未修改的 T085 Agent `eb6875699d3fdb92e3340a0a0af106fcf30f2985d490389f81fe3a0823c209f8`，独立诊断插件 `b497712e8e4b98ab8f95e5b458e5a5afacc72635987361394a7ea47760fbdf56`。同 heavy 模型、711 来源、配置、设置只读启动探针、唯一 premain、禁止 attach；一个 JFR 和一个 GC 日志选项，无 ThreadMX 覆盖、强制 GC 或宿主字节码诊断覆盖。

每轮在原生命令输入绑定之前，取已绑定文档唯一 ModelingView 的实际 `getComponent().getJComponent()`。要求控件显示、尺寸有效且有鼠标移动监听器，在同一 EDT 派发画布中心的 `MOUSE_MOVED`：无按键、无点击、无拖拽，不移动系统指针。要求原生 `m.i` 与该画布控件为同一对象、视图 `lastMouseEvent` 为真实原生事件，否则任务拒绝。仅触及自有任务文档，不写原生静态字段或修改其他窗口。输入派发发生在 CPU/JFR 命令区间之外；派发后再绑定当前源版本，避免把准备阶段的刷新算进命令版本变化。

保留 T090 的原字段快照、字符串交接和驱动线程写入。六条输入记录必须显示非空控件及原生鼠标事件。标准身份/模型/config/部署、正常退出/kernel 清理、2133 行有序来源/位置/数组形状、独立内核 CPU 单位、同 JFR 任务/EDT/30 字段和完整栈检查保持。七字段历史参考逐行比较：索引差异仍记录 FAIL，不因诊断目的覆盖失败；保留全部不匹配项、输入状态、JFR 及输出后再分析。

离线实际插件 loader 和 7 个打包 helper 检查通过；新的 Swing 事件控制只证明事件无按钮/中心坐标/监听器派发及空尺寸/EDT 拒绝，不声称真实画布派发已成功。原生控件/监听器作用由本次实机验证。T090 已核验的真实 SDK 字段没有改动。

预期会观察到非空控件、可能的复制刷新链及有效缓存；不预设必须复现 T089 的精确索引差异。采样缺席不是未执行的证明。T089 当时的输入状态仍缺失，受控复现不能补造历史因果；T088 RSS 原因仍待证明。禁止将诊断时长解释为正式性能收益，既有失败、T057 接受交付及完整多版本/长期/Lane C 范围保持。
