# T090 原生输入状态独立诊断

目的：读取真实命令前后的原生输入状态，结合同一 JFR 时钟的完整栈及缓存快照，区分“动作派发路径是否发生”和“来源/几何是否一致”。只有一次 5303 FIFO 任务，不替换或重试 T087/T088/T089，不授予性能验收。

生产 Agent 使用原 T085 SHA `eb6875699d3fdb92e3340a0a0af106fcf30f2985d490389f81fe3a0823c209f8`，不含 ThreadMX 内存覆盖。独立插件 SHA `d486a2b2789acf8e2b71b667e43da4ddf4e4aee6ad89959e728ba38158ed5e8d`。同一 heavy 模型、711 来源、三个原生命令、重建/保留边界选项、配置、设置启动只读探针、唯一 premain、禁止 attach；不改变鼠标、子工具或原生静态事件控件，不强制 GC。一个 JFR 配置、一个详细 GC 日志选项。相对历史诊断存在多项差异，禁止直接归因于单一变量或将速度作为优化收益。

快照在同一命令 EDT 上、CPU 测量区间前后读取：静态鼠标事件控件 `m.i`、静态子工具、文档视图的 `lastMouseEvent` 原始标量和 `_lastActionPack` 身份。使用原字段，不调用惰性几何 getter、对象 `toString/equals/hashCode` 或修改原生对象。通过只含字符串的原子交接移出 EDT，再在驱动线程写入六条 Base64 编码记录。身份 hash 仅用于展示，不能单独证明对象唯一性或跨进程一致性。

离线要求：实际生产 ZIP 检查/插件 loader、打包 helper 控制（CPU、数组、输出写入、JFR 时钟、输入交接与线程边界）、真实 5303 SDK 四个字段类型/静态性检查。真实调用 `getViewContexts` 返回文档视图仍需宿主验证；离线没有声称完整动作上下文已复现。

冻结实机检查：标准 PASS、模型/config/部署工件身份、正常退出及内核清理；六条有序输入记录、2133 行有序来源/输出、点数与位置参考一致、数组形状和版本不变量；独立内核 CPU 单位检查；三轮 JFR 任务/EDT/30 CPU 时间字段绑定及完整调用链审查。七字段历史输出参考仍逐行比较；索引不一致明确报告 FAIL，并保留输入、JFR、输出和所有不匹配项后继续只读分析，不删除或改写失败。

T090 不要求必然观察到某条调用链：记录到是动态证明，没有采样到只能报告“未采样到”。实际控件值与缓存状态的相关性不是因果证明。T086、T088、T089 失败及 T057 已接受交付保持；三版本真实宿主、长期和 Lane C 尚未完成。

提交前由同名 JSON 冻结准备摘要、完整输入 SHA、分析脚本及一次性 controller。共享 FIFO 不插队，不处置其他任务/用户窗口；观察超时不代表任务结束，也不允许重新提交。
