# Real Import Entry Host Driver

This validation plugin must sit in an isolated task bundle together with the production `plugins:model-import-3d` plugin. It triggers an import through the real menu, the colour dialog, the runtime file chooser, and the confirmation dialog. It never links to or calls `SurfaceImport` directly and injects no fixed file grant. Control operations use the public Swing API, not a mouse robot.

The driver creates a task document from a read-only seed, sets a 1024 canvas, selects "keep original material", and picks the frozen `artifacts/cube-textured/cube-textured.glb`, whose embedded texture was added from the authorized `cube.glb`. Through the SDK it records six meshes, the 45×45 binding, the resources, and the state of one Undo/Redo. The report explicitly does not prove rendering, save and reopen, or wider input support. The task exits its dedicated JVM when it ends, and the shared queue supervisor decides the lifecycle separately. Never install this validation plugin in a user work session.

`build.py --sdk <SDK.jar> --agent <turboism-agent.jar> --out <fresh worktree build subdirectory>` only compiles, checks the packaging, and freezes the provenance; it neither runs nor submits a host. A real host test also needs the package identity checks of the production plugin and the latest runtime, a queue prepare, an independent admission review, and a submission.

The build uses the actual `PluginJarContract` inside the frozen agent to check language resources, entry points, and resource declarations, and it runs three refusal comparisons: a missing language resource, a missing entry point, and an undeclared language resource.

`verify-report.py --texture artifacts/cube-textured/cube-textured.glb` verifies the fixed hash of the new input, unchanged original geometry and UV bytes, the complete UV and image coordinates, the single shared image binding, and Undo/Redo. Omitting that option serves only a historical FACE_COLORS report. Neither proves that native pixel sampling is correct.

`verify-texture-pixels.py` is an independent source-texture pixel checker with nine fixed key poses (-30, 0, and 30 on each axis), a 1024 canvas, and 200 pixels per source unit. Source 3D depth decides the visible face, and source UV computes top-row-first CLAMP_TO_EDGE/LINEAR sampling; the four-pixel grid excludes only one pixel at the edge of a projected triangle, never texture text or arrows. The RGB tolerance is 2 and alpha must match exactly. It needs nine PNGs captured separately by the host, and an outer layer must verify state, pose, history, and lifecycle. So far only the offline self-test passes; no comparison with native screenshots exists, so it is not host acceptance.

The new `SourceTextureCapture` reads native rendered pixels for those nine poses through the SDK after the menu import and Undo/Redo finish. Every pose requires a fresh parameter consumption record; the run saves evaluation, history, and protection state digests before and after rendering, and finally undoes the parameter change the capture made. The protection state keeps meshes, resources, control hierarchy, and parameter definitions and excludes only the current parameter values; the complete original JSON ships with the report for independent binding.

A new driver must be frozen again before submission, and an already queued old test never gains screenshots automatically. Check the capture result with `verify-texture-pixels.py --report <report.json> --cube <original cube.glb> --texture <cube-textured.glb> --artifacts <collected artifact directory> --run <run-id> --out <result>`. Job identity, package identity, and lifecycle still come from the outer admission check. In the current offline structural test the pixel stage explicitly uses a placeholder function and verifies only the state gate, so it never counts as a real rendering pass.

## Surface menu persistence profiles

`--surface-fixture plane|seam --surface-save` builds the explicit `plane-menu-save` or `seam-menu-save` SDK-only driver. It uses the real production menu and chooser, verifies single Undo/Redo and nine fresh source rasters, and then calls the typed reject-existing SAVE_AS. The isolated runtime grants only `mi3d-surface-menu-save` to the UI validation plugin, at `persistence/mi3d-surface-model.cmo3`, with both the exact mode and the save opt-in. The artifact budget is 64 MiB and does not inherit the apple budget.

`--surface-reopen` builds the observe-only `plane-menu-reopen` or `seam-menu-reopen`; the bundle pins `seed.cmo3` to the accepted SAVE_AS hash, bytes, job, and prepared identity. Reopen profiles hold no file grant and create or import no model. `verify-surface-reopen-job.py` rechecks the complete saved job before admitting a distinct job, run, and attempt, and then checks all stored geometry, forms, resources, and parameters plus nine PNG identities. `test-surface-save.py` and `test-surface-reopen.py --save-artifacts <accepted-save-artifacts>` are synthetic refusal checks and cannot prove native persistence. Full intermediate poses and the official export are separate gates.
