# Real Native ACP Observation Probe

The standard task `mcp:5303@native-observe` runs only on an exact 5.3.03 task copy. Run `scripts/preview/package-mcp-native-observe-validation.sh` first, then use the existing worker through `host_validation.py prepare/submit/status`. Never start the host directly.

The auxiliary bundle holds the production ACP and SDK classes of this workspace plus the test-only NativeObserve entry point. The queue pins the auxiliary bundle, the runtime manifest, the Java and Node executables, and the complete Pi 1.2.0 release tree (the default route); a runtime change refuses execution. The 5.3.03 restriction is the test scope of this new integration case, not a production API version admission change.

The real Pi starts through the production AcpClient → NativeAgentTransport → NativePiProvider path. Pi built-in tools, automatic extensions, skills, and prompt templates are disabled, and only the production MCP extension loads explicitly. The model and authentication of the user's existing CLI are reused and read by the CLI itself; no authentication configuration is copied, printed, or archived. The permission callback denies by default. The standard-input MCP forwarder exposes only render.state, capture, two resources, and the resource directory, and rejects parameter, geometry, file, history, and pose writes; it allows at most 32 requests and 2 images of 512×512 and never replays a failed request. The token comes only from the task-private token file read by the task forwarder and never enters the agent session parameters.

The probe transparently observes the provider, id, and input of the native `get_available_models`, keeps the current model when it supports images, and otherwise selects a runtime-declared vision model through the production session configuration; with no candidate it refuses before the prompt. The second argument of the auxiliary bundle build script accepts a comma-separated provider exclusion list pinned into `runtime.json`; it applies to new tasks only and never switches or replays inside a failed turn. The Pi 1.2.0 RPC `set_model` calls `session.setModel(model)` without setting `persist`, so it does not save the model as the user global default. A runtime declaration of availability does not prove that the account is unexpired, that quota remains, or that the model request really succeeded.

The host native PNG, the real model answer, and the session stay in the private task directory. The run separately verifies the production PNG hash, the ACP typed image callback hash, and that the document and history are unchanged; a text description from the model still needs a manual comparison against the real image. `CAPTURE_DELIVERED_REVIEW_REQUIRED` is no visual quality or complete auto-modelling pass, and `modelVisionAccepted` defaults to false. A Linux production client callback here is not acceptance of the Cubism Swing window display.

The probe starts only the sidecar process group it created and kills only that group on timeout; the host lifecycle and cleanup still belong to the standard queue. Closing the harness does not claim to cancel a host operation. The observation route accepts no write and no multi-step rig orchestration; a controlled write uses the separate native-edit route below.

## Claude Native Observation Route

`bash scripts/preview/package-mcp-native-observe-validation.sh claude` builds the test-only Claude route, after which the same standard prepare/submit/status flow applies. Runtime manifest v2 pins Java, the Claude 2.1.284 executable, and the complete installation tree; v1 keeps the Pi default route. No authentication configuration is copied; a real model request is handled by the external service configured in the existing CLI, and the scope of the test image, the active document metadata, and the tool results sent must be authorized before use.

Claude runs with restricted mode, a strict MCP config, empty setting sources, and disabled hooks, plugins, slash commands, browser, and session persistence, and it allows only the two built-in resources plus the controlled MCP. The permission callback denies by default, and one CLI run is capped at 2 USD. The tool set declared by the runtime `system/init` must also pass a closed check; an unknown or extra execution tool is rejected, and the list is never widened to make a test pass.

This route has no reviewed runtime-declared vision metadata, so it first sends a random image probe: 512×384 with a six-digit random number and four coloured positions, and the model must return exact JSON without calling a tool. Only when the answer matches completely and the tool set is safe does the run issue the private canary gate and open the host resources and rendering; a change of model or tool state refuses. The gate rejects symlinks, over-limit input, and extra fields. This proves only that this input was consumed, not artistic quality, host image understanding, or the vision ability of every model. The probe PNG, the answer, and the expected value stay in the task-private directory, and the public report keeps only the necessary booleans and hashes.

The first task failed before starting Claude because of an empty argv and was fixed to `--setting-sources=`; the initialize and new-session handshake with the full restricted parameters passed, and no model prompt was sent. The fixed second round was prepared, but the submission was refused by automatic approval and has not entered the queue; it waits for explicit authorization to send test content to the external Claude service. See section 63 of the audit verification.

### Codex 6.1 Sol Controlled Observation

After the user explicitly chooses Codex, run `bash scripts/preview/package-mcp-native-observe-validation.sh codex` and then the same `mcp:5303@native-observe` standard prepare/submit/status flow. schemaVersion 3 pins the local Codex 0.159.2, `gpt-6.1-sol`, Node and Java, and the hash of the whole CLI installation tree. It copies no user configuration or credential and falls back to no other model.

Before launch it runs a prompt-free `config/read` precheck with the same argv and working directory: read-only sandbox, on-request approval, and disabled shell, apply_patch, view_image, web, model code mode, plugins, subagents, memory, and host skill discovery, with inherited MCP cleared; the production ACP session then injects the specified read-only agent. A configuration field mismatch refuses. This check proves the configuration took effect and is no independent proof of the complete model tool inventory. The permission listener keeps denying by default, and the host MCP proxy offers no write operation.

The model must explicitly declare image input in the runtime `model/list` and first answer the random captcha and colour canary correctly. Only then does the run issue the private gate bound to the harness and the exact model, which allows reading host resources and calling the renderer. Whether the model really understands the host rendering still needs a manual check, and a canary or an ACP callback alone cannot assert a pass. This sidecar has no Swing window and is no end-to-end acceptance from a real model to Swing.

Protocol and configuration sources: the [official app-server documentation](https://developers.openai.com/codex/app-server) and the [official configuration reference](https://developers.openai.com/codex/config-reference); the actual run follows the schema generated by 0.159.2, the real model/list and config/read, and the host result.

The internal Codex `code_mode_host` stays enabled because it carries the MCP tool execution infrastructure; disabling it makes discovery work while every call returns "code-mode host is disabled". The model code_mode, shell, and other tools stay off. Disabling an internal execution component is never tool isolation, and a real MCP call must pass on its own.

### Codex Controlled Keyform Write

After the user explicitly authorizes sending synthetic model coordinates and a controlled write, run `bash scripts/preview/package-mcp-native-observe-validation.sh codex keyform-edit` and then the `mcp:5303@native-edit` standard prepare/submit/status flow. schemaVersion 4 pins `workflow: keyform-edit`, and the queue refuses to mix an observation and an edit manifest. The task's `readOnlyInspection=true` disables only the extra change of the Java base probe, while `nativeEditing=true` explicitly enables the Python controlled-edit verification; this task is not a read-only test.

The local verifier picks one independent non-default ArtMesh form of the synthetic copy and passes only the identity and the complete bound axis tuple as scope, never a prepared coordinate change. The model must read the complete pagination of the same snapshot, build the complete positions itself, preview successfully, write once with the exact same request, and read again. The proxy accepts only a positive x movement of one vertex, no larger than min(4, x span / 32), with all y values and all other vertices unchanged; it rejects a default, shared, or out-of-domain form, an unknown business parameter, extra objects, and file, history, or parameter writes. An MCP protocol extension field is still dropped and never reaches the host.

The independent verifier checks the complete stored rows of the target and of the sample Warp and Rotation, scans the native render difference before and after the target pose, runs guarded undo and redo, and finally undoes and verifies that the parameters and the identity are restored. The model consumes at most two 512×512 images of the current pose; the local verifier checks the target form pose image separately, and the model must not be claimed to have observed that target pose. This run saves no file and modifies no original.

A write timeout is never replayed; the same operationId only queries the result. A restore is allowed only with an exact receipt and a matching history identity; an attempted write without a receipt is recorded as OUTCOME_UNKNOWN and never blindly undone. Closing the sidecar does not prove that the host cancelled. A report keeps the failure evidence even when the restore check fails. See the [audit verification record](../acp-auto-modeling-capability-audit/verification.md#68-codex-controlled-single-vertex-write) for the real task result.
