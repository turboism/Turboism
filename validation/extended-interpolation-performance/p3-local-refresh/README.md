# 保留通知的局部刷新

## 当前生产接入

局部固定点跳过已接入生产 bridge，具体门禁、最新生产包与验收结果见 [生产落地报告](production.md)。下面保留先前隔离原型的实验身份与结果，不将其与生产安装矩阵混用。

## 历史原型结论

**Normal 切片级局部计算跳过有可行切口。** 5.3.04 先验通过，再对收录的 20 个稳定工件验证：ArtMesh / Warp / Rotation × ELLIPSE / SNS × 两轴 / 三轴，**每版 12 用例、264 个更新后快照**；所有数值状态 raw bits、绝对 EditVersion、实际 `setUpdated()` 对象顺序一致。不能把该隔离原型等同于已安装的生产优化或实际交互提速。

原先“坐标一致但版本增量不一致”的阻断，已在这些实验中由**实际通知轨迹重放**解决。此前否定的是直接删掉干净切片调用，不能推导成局部计算永远不可行。

该原型阶段的生产 bundle 未改变，当时为 `044b0148e395b94ad7d7b76ebe4b3a997796b9659fb318197f0918c15f26d5b4`。本目录的探针代码不进入 runtime 或安装包；当前生产实现另见上述报告。

## 最小切口

不拦截 `force=true`，不删除 Part 广播，不修改 Normal/Morph 的外层遍历，不自行重排各轴。

1. 在每次原生 common 入口记录源与目标的全部数值/布尔字段、坐标和颜色 raw bits。包括 ArtMesh 的 `drawOrder` **及 `_drawOrder`**、Rotation 的 origin/angle/scale/reflect、各层 opacity/颜色；排除 EditVersion 和调试实例号。另记录曲线类型、scale、锚点/区间/插入标志/比例与弧度常数。
2. 记录 extension、form、keys 及可变坐标数组/颜色/坐标系对象的身份，避免模型或存储替换被当作同一次结构。
3. 执行原生 common，动态记录真实 `ACForm.setUpdated()` 的每次目标索引及顺序。**不从 target 列表成员数或统一顶点数推算**。
4. 仅当这次原生执行前后的所有目标数值完全相同，才将其记为可跳过片。这是一次实际固定点观测，不假设所有 common 恒等或幂等。
5. 后续同一片的身份、完整输入与当前目标状态均相同时，跳过数学、属性混合及重复坐标写回，但依原轨迹逐次调用官方 final `setUpdated()`。任何不匹配继续原生并重新观测。

按原生轴顺序逐片检查，所以前序轴真的改变输出时，后序片的源快照也改变，自动重算；不需要把每个保守脏片的全部 target 成员都扩散为脏。每片目标状态也纳入输入，直接修改派生形态不会误跳过。

这是“干净片省计算、更新契约保留”。并未消除逐片检查和逐次版本递增，也未声称普通滑块/播放需要刷新。

## 证据

- [完整 20 工件矩阵和源码指纹](evidence/matrix/manifest.json)：先 5.3.04，再 5.0.00–06、5.1.00–03、5.2.00–03、5.3.00–03。没有覆盖 4.x、beta 或未来版本。
- [目标版逐步日志](evidence/matrix/5.3.04/proof.log) / [机器摘要](evidence/matrix/target-summary.json)：22 步，包含重复无变化、连续普通源点变化、仅 opacity/颜色变化、不增加版本的坐标变化、直接修改派生形态、负 scale、曲线切换、插入点数/结构重建和对象特有属性变化。
- 每版总计跳过 5,608 次 common 计算；包含无变化步骤，**不能当作单源编辑的平均跳过量**。
- [负对照](evidence/negative/5.3.04/proof.log)：仅禁用通知重放，第一次实际跳过（step 1）立即因 setter 顺序不等而失败；证明断言不会把“只保坐标”误计为通过。
- [通知原语审计](evidence/setter/summary.json)：逐工件 javap 检查 `ACForm.setUpdated()` 为 final，只有读取 editVersion、加 1、写回，无调用其他方法。各版实际指令在对应 `setUpdated.txt`。这只证明该通知原语，不替代所有其他 setter/混合副作用审计。

### 单普通源点连续变化时的跳过量

只统计 step 3–10，6 个对象/曲线组合，共 48 次更新/轴数：

| Normal 网格 | 单次跳过比例范围 | 合计跳过 / 原生 common 次数 |
| --- | --- | --- |
| 两轴，每轴 3 个源锚点，每区间 2 插入点 | 20%–40% | 138 / 480 |
| 三轴，同样锚点与插入点 | 41.8%–60.8% | 1,968 / 3,792 |

区别于早期基于保守脏图的 14.3%/27.8% 实验：本轮检查真实数值传播与目标当前状态，网格参数也有区别；不能跨实验直接归因提速。未测 wall time、分配或 FPS，也没有把被跳过的计算占比等同于耗时下降。

## 尚未放行的边界

- **Morph**：当前探针对含 Morph 的 owner 显式终止，不构造 Morph 场景，也不把 Normal 证明外推到 Morph。生产实现应先整对象回原生，另做 Base/Morph 编辑、属性、历史、保存及参数求值专项。
- **身份及缓存生命周期**：原型使用仅测试 JVM 内的强引用 IdentityHashMap，便于精确追踪；无生产内存预算/弱引用清理，绝不能直接搬进 runtime。主包现有数值 LRU 的引用回收结论不适用于这个实验表。
- **输入与副作用**：反射快照覆盖本轮三种已知 form 的数值/颜色字段，不是任意插件字段或所有外部依赖的通用证明。正式适配须明确读取白名单及全部相关原生写入/回调，未知字段/类/共享可变数组或颜色别名/非有限值/不明并发状态回原生。
- **完整交互契约**：没有 Editor 活体鼠标、官方 Undo/Redo、GL、保存/独立 JVM 重开或并发读者实测。步骤中的数值修改不是官方历史操作。通知轨迹一致并不单独证明所有并发可观测中间写入一致。
- **性能**：原型有装箱、反射、全目标扫描和逐次轨迹保存；所有测试都带验证插桩。未测相对 P1/P2/P3 的净收益，不建议以此原型默认开启。

## 可执行的生产推进顺序

1. **限定 Normal 准入**：在已验证的 common seam 上接入本轮固定点门禁；保留原生 force、外层遍历和轴顺序。Morph/未知类型/非有限值/别名/结构身份改变继续原生。
2. **实现有界、可释放状态**：用明确类型的 MethodHandle/数组访问代替逐帧反射和装箱。采用仅存基本类型的完整签名与相对目标索引通知轨迹，或有明确生命周期的弱身份状态；建立条目/字节上限、单条超限回退、禁用清空、关闭/重建/异常清理。不能复用本探针的全局强引用表。
3. **不新增全局 setter hook**：验证 agent 的 ACForm 插桩只用来建立 oracle。正式路径可在已有 bridge 的实际写回点记录等价轨迹；每次实际通知仍调用官方 setter，避免全局拦截其他编辑工作。
4. **再做增量 A/B**：基线是当前 P1/P2/P3 包，不是仅官方原始内核。分别测连续变化、重复、仅属性、历史往返、2/3 轴、小/大网格和预算抖动；包含签名扫描、通知重放、分配与 p95/p99，收益不足即不启用。
5. **放行验证**：重跑每版状态/绝对版本/通知顺序、拒绝不写入及生命周期；5.3.04 真实拖动、全 bank 官方历史、级联、GL、保存及独立重开。最后单独覆盖 Morph 后才扩大准入。
