# MaxRects-BSSF レイアウトアルゴリズム

> **Turboism 公式プラグイン** · **ステータス: プレビュー**

Cubism のテクスチャアトラスワークフローに MaxRects-BSSF 自動レイアウトアルゴリズムを追加します。

| 詳細 | 値 |
|---|---|
| バージョン | `0.1.0` |
| プラグイン ID | `dev.turboism.plugin.texture-atlas` |
| カテゴリ | `modeling` |
| タグ | texture-atlas, packing, auto-layout |
| Turboism API | `[0.1.0,0.2.0)` |
| Cubism が必要 | はい |
| インターフェース | `none` |
| ライセンス | プロジェクトライセンス |

## 機能概要

- テクスチャアトラスエディターに MaxRects-BSSF とネイティブのレイアウト選択肢を登録します。
- ネイティブ自動配置では、今回渡された現在のテクスチャページの画像のみを処理します。固定/自動倍率、回転、ページ内の領域並列探索に対応し、配置できない項目はネイティブの overflow に返します。他ページは探索しません。明示的な全アトラス SDK リクエストは別経路を維持します。
- 選択されたレイアウトモード、アルゴリズム、並列探索設定を永続化します。

## 要件と互換性

- **Turboism API:** `[0.1.0,0.2.0)`。
- **Cubism:** Cubism が必要です。Turboism は現在、レビュー済みの厳密な Editor 成果物 `5.2.03`、`5.3.02`、および `5.3.03` を受け入れます。このプラグインは、宣言されたサービスと機能が利用可能な場合にのみ、各ホスト向け機能を公開します。
- **インターフェースモード:** `none`。
- **プラグインの依存関係:** 宣言されていません。

## インストールと有効化

この公式プラグインは**ストア候補**であり、まだストアリスティングとして公開されていません。マーケットプレイス公開までは Turboism の公式リリースパッケージからインストールし、**プラグイン管理**で有効にしてください。ワークフローが不要な場合は、同じウィンドウから無効化またはアンインストールできます。

## 使い方

1. Cubism のテクスチャアトラスエディターを開き、自動レイアウトワークフローを選択します。
2. MaxRects-BSSF またはネイティブアルゴリズムを選択し、並列探索を有効にするかどうかを選びます。
3. 自動レイアウトを実行します。プラグインは適用前に完全なプランを検証します。

### 過去のCircle入口ベンチマーク（保持）

本作業ツリーのプレビュー実装を、隔離した Cubism 5.3.03 / GE-Proton10-34、Java 17.0.3.1、i7-9750H / Xvfb llvmpipe で計160回実行しました。各サイズで両実装を20回ずつ実行し、最初の4回をウォームアップとして除外。残る16回（アルゴリズム切り替え直後8回、連続使用8回）の、同じメソッド入口から戻りまでの中央値です。

| 100 | 4096² | 101.49 | 71.76 | **1.41×** |

メッシュモード、margin=3、自動倍率、回転許可、並列処理オフ。毎回 Undo 後の入力ハッシュが一致し、実行分岐と幾何検証に合格しました。両実装とも倍率1で全画像を配置し、重なり・ページ外へのはみ出しはなく、item と可視 LayerRef の変換が一致しました。

**制限：**UI全体の所要時間や、すべてのモデル・legacy に対する保証ではありません。margin のヒューリスティックはピクセル単位では同一でなく、この条件では縮小や overflow は発生しません。切り替え直後の遅延や遅いサンプルも含めており、並列処理が常に速いとは限りません。高密度ページ、並列処理、複数ページ、保存後の再オープンは引き続き検証が必要です。

### Geometry：サイズと形状が異なる画像

Circle は同一モデル内で等しいサイズの円、Geometry はサイズと形状が異なる幾何画像です。以下は新しい統一キューの DW-Proton 環境で、従来の Circle の GE-Proton/Xvfb 環境とは異なります。各実装を別の新規ホストで一度だけ実行した値であり、**ウォームアップ後の中央値ではありません**。環境やデータセットを混ぜて比較しないでください。

| Geometry 画像数 | テクスチャ寸法（px） | ネイティブ ms | 新実装 ms | 単発の時間比 | 両者の倍率 / 配置数 |

| 100 | 4096×4096 | 2470.633 | 109.1223 | 22.64× | 1 / 100 |
| 500 | 8192×8192 | 240731.9269 | 336.6122 | 715.16× | 1 / 500 |
| 1000 | 8192×8192 | 1634730.3306 | 404.6034 | 4040.33× | 1 / 1000 |

100/500/1000画像の両実装は入力同一性、幾何、公式ファイル識別、ファイル不変、正常終了、結び付けたcgroupのクリーンアップ確認に合格しました。1000画像のネイティブ処理は27分14.73秒でした。[Geometryキューレポート](../../validation/texture-atlas-current-page/HOST-GEOMETRY-QUEUE.md) と [合格した6件の生データ](../../validation/texture-atlas-current-page/host-geometry-queue-samples.csv) を参照してください。

最終2500：新実装の逐次処理を一度だけ実行し、**11544.0627 ms**、8192²ページ、**倍率0.97265625**で全2500画像を配置、管理器の完全PASSを取得しました。**ネイティブは2時間を超えても完了せず、ユーザーの指示で中止しました。** 管理器は対象cgroupの安全なクリーンアップを確認しましたが、正常終了やネイティブ検証PASSではありません。完了時間・最終倍率は未取得のため、速度比は算出しません。再試行なし。固定prepared/job IDは [2500単発検証台帳](../../validation/texture-atlas-current-page/HOST-GEOMETRY-2500-ONCE.md) を参照してください。

追加の [高密度ページ機能検証](../../validation/texture-atlas-current-page/HOST-DENSE.md)：500画像/1024²ページで自動倍率は新実装0.3826、ネイティブ0.3450となり、両者とも全画像を配置しました。固定100%・回転なしでは新実装81枚、ネイティブ51枚を配置し、縮小せず残りをoverflowに返しました。3つのForkJoinワーカーによる領域処理を確認しましたが、この少数サンプルでは並列化による品質向上はなく、連続呼び出しは遅くなりました。上記速度比は更新しません。overflow後のネイティブUndo一回で全入力が復元されない現象は調査中です。

## プライバシーとデータ

### ネットワーク

ネットワーク接続は行いません。

### ローカルデータ

レイアウト設定を `texture-atlas/layout.cfg` のプラグイン設定に保存します。ワークフローの実行時にのみ、アクティブなテクスチャアトラス作成状態を読み書きします。

### テレメトリー

このプラグインからテレメトリが送信されることはありません。

プラグイン ID が付与されたプラグインのライフサイクル記録および障害記録が、Turboism のセッションログと Cubism のホストログに表示される場合があります。

## 状態と制限

オフラインでの追加改善：32 項目未満の並列要求は先に直列配置を試し、不完全なら領域候補も維持します。分割開始閾値は 16 のままです。120 合成ケースで配置数と倍率は不変でしたが、一部の時間は悪化しており、常に高速とは限りません。自動倍率は有界ヒューリスティックで、最大値を保証しません。[オフライン証拠](../../validation/texture-atlas-current-page/OFFLINE-POLICY.md)を参照してください。既存の実機表は本変更と q ガードより前の測定で、この段階では実機を再実行していません。

- **ステータス:** プレビュー。
- アクティブなテクスチャアトラスエディターセッションと、レビュー済みのモデル読み取り/書き込みサービスが必要です。
- 計画または適用の失敗は部分的なレイアウトを適用せずに報告されます。ネイティブアルゴリズムはフォールバックとして引き続き利用可能です。
